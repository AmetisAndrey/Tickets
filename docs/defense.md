# Отчёт и сценарий защиты проекта

## 1. Краткое описание

Проект — REST-сервис обработки заявок технической поддержки. Он централизует регистрацию обращений, контроль жизненного цикла, хранение истории статусов, поиск и получение статистики. Архитектура: один Spring Boot сервис и PostgreSQL.

## 2. Реализованные функции по исходному коду

- создание заявки со статусом NEW;
- получение по ID;
- изменение описания, приоритета и срока открытой заявки;
- переходы статусов с проверкой машины состояний;
- запрет повторного открытия и редактирования закрытых заявок;
- история, включая начальное `null → NEW`;
- фильтры статуса, приоритета, категории, `overdue=true` и пагинация;
- справочник категорий;
- отчёт по периоду: количество, распределения, просрочка, среднее время решения;
- обработка типовых ошибок 400/404/409;
- PostgreSQL, Flyway, Docker Compose и health endpoint.

## 3. Технологии

Java 17, Kotlin/JVM, Spring Boot 3.2.5, Spring Data JPA/Hibernate, PostgreSQL 16, Flyway, Gradle Wrapper, JUnit 5, Mockito/Mockito-Kotlin, Testcontainers, Springdoc/OpenAPI, Docker Compose.

## 4. Интеграция Java и Kotlin

Java `ReportController` вызывает Kotlin `ReportService`. Kotlin получает данные через Java-интерфейс `TicketReportDataPort`; `JpaTicketReportDataAdapter` выполняет JPQL через `EntityManager`.

Особенности Kotlin:
1. `data class` (`ReportSummary`, `TicketReportRow`) описывает модели отчёта и автоматически предоставляет методы данных.
2. Nullable `Double?` отражает отсутствие среднего времени решения как `null`; применяются `takeIf` и safe-call `?.average()`.

## 5. Тесты

По исходникам обнаружено: 11 Java unit, 6 integration, 2 E2E, 5 Kotlin — всего 24 тестовых метода. Testcontainers использует PostgreSQL 16; время управляется через Clock и тестовый MutableClock. Это подсчёт тестов в исходниках, не доказательство успешного запуска. Перед защитой сохранить отчёт Gradle и coverage. `TicketReportDataPortTest.kt` мокирует интерфейс, поэтому нужен Kotlin-тест реального `JpaTicketReportDataAdapter` для полного соответствия критерию проверки Java-компонента.

## 7. Итоги
Основной Java REST-функционал, Kotlin-отчётность, модель данных, миграция и тестовые сценарии уже присутствуют. Для завершения практики необходимо устранить конфигурационные замечания, подтвердить тестирование отчётами, закрыть требование о тесте реального Java-компонента из Kotlin и настроить CI/CD с демонстрацией развёртывания.
